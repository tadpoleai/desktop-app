# 标定全景生成优化：MediaSDK 实测与当前方案

> 测试数据：`20260802185640_fred_home.insv`，159.826 秒，29.97 FPS，4790 帧。  
> 测试环境：Ubuntu 22.04，NVIDIA RTX5880 Ada 8GB，MediaSDKTest 镜像 `hera-panorama-stitch-gpu:latest`。

## MediaSDK 按帧导出实测

`MediaSDKTest -help` 提供：

- `-image_sequence_dir`
- `-export_frame_index`

但这些参数只控制最终导出的帧，不会让拼接计算在目标帧后提前结束：

- optflow、3840×1920、目标第 300 帧：运行 266 秒仍无图片产出，人工停止；
- optflow、纯图片模式、不生成 mp4：运行 242 秒仍无图片产出，超时停止；
- template、1920×960、目标第 0 帧：运行 46 秒仍无图片产出，人工停止。

因此，在 UI 增加导出区间或频率只会减少输出文件数量，不能解决首次拼接耗时，当前不接入这个无效参数。

## 已实施方案

标定页面增加会话级全景复用：

1. 默认查找相同 INSV 路径最近一次成功的 `calib_panorama_frame`；
2. 要求 `panorama.mp4` 和 `frame.jpg` 均存在、非空；
3. 要求两个产物的修改时间不早于源 INSV，避免源文件被替换后误用旧缓存；
4. 命中后跳过 GPU 拼接，只从缓存视频按用户指定时间重新抽帧；
5. 用户可关闭“优先复用”强制重新拼接。

标定页面同时增加“初始全景帧时间”，首次拼接完成后直接抽取指定秒数；缓存命中时同样从缓存视频抽取该时刻。

## 后续首次拼接优化

首次拼接仍必须处理完整 INSV。后续可独立验证：

- template 与 optflow 的总耗时差异；
- template 接缝处特征位置误差是否满足标定要求；
- 能否使用保留 Insta360 专有 MP4 box 的工具生成短片段；普通 ffmpeg 重封装已确认会丢失镜头标定元数据，不应恢复。
